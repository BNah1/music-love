# architecture

Read the project's AGENTS.md, CONTROL.md, applicable governance, and canonical task first. Follow Owner authority and current gates. Use project-root-relative artifact paths; update the existing task rather than creating a parallel registry. Load only relevant context. This skill is portable Markdown and requires no BMAD runtime.

Use Planner responsibility. Inspect existing architecture first. Document only decisions relevant to the change: system boundaries, interfaces, data flow, ownership, deployment constraints, alternatives, tradeoffs and migration implications. Link the architecture spec from affected tasks. For a local change following established patterns, a short task note may suffice. Resolve consequential unknowns under CONTROL policy. Do not prescribe a language or framework without project evidence.
