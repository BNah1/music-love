# product-planning

Read the project's AGENTS.md, CONTROL.md, applicable governance, Master Plan and active phase first. Read a canonical task when revising or replanning it; new work may not have one yet. Follow Owner authority and current gates, use project-root-relative paths and load only relevant context. This skill is portable Markdown and requires no BMAD runtime.

Use the Planner role; the Product Owner specialty does not grant human Owner authority. Distill intent, outcomes, exclusions, acceptance criteria, dependencies, open decisions, and risks from supplied sources. Size the work: one bounded change gets a task; several related changes get a phase. Keep specs in project_management/specs and link canonical tasks from the phase. Assign unique IDs after checking active and archived tasks. When intent changes, identify affected tasks, evidence, and dependencies; preserve prior decisions, explain supersession, and revise only authorized scope. Advance tasks to READY only under CONTROL approval policy.
