# handover-takeover

Read the project's AGENTS.md, CONTROL.md, applicable governance, and canonical task first. Follow Owner authority and current gates. Use project-root-relative artifact paths; update the existing task rather than creating a parallel registry. Load only relevant context. This skill is portable Markdown and requires no BMAD runtime.

Read current role pointer, canonical task, current CONTROL and relevant evidence. Compare checkpoint revision with actual working tree; identify unfinished writes or processes before new edits. Append an acknowledged handover identifying sender/receiver, roles, checkpoint, unknowns and next action. If sender vanished, label the entry reconstructed. Claim affected role files; do not erase old history. Apply current quota fallback: implementation by the former reviewer requires fresh independent review or the explicit SELF_REVIEW exception. Reuse unchanged valid evidence; rerun checks invalidated by changes. Return roles to IDLE when released, preserving history.
