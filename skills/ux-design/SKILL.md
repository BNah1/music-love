# ux-design

Read the project's AGENTS.md, CONTROL.md, applicable governance, and canonical task first. Follow Owner authority and current gates. Use project-root-relative artifact paths; update the existing task rather than creating a parallel registry. Load only relevant context. This skill is portable Markdown and requires no BMAD runtime.

Use Planner for design and Executor only when implementation is assigned. Read applicable ui_ux and assets rules, current design system, users and acceptance criteria. Specify journeys, screens, navigation, loading/empty/error states, responsive or platform behavior and accessibility requirements. Record decisions and review criteria in a linked spec; reuse existing components. If visual prototypes are requested, use available tools and state their fidelity. Design does not imply permission to replace assets, add dependencies or change product scope. Defer pixel-perfect claims until implementation is visually inspected.
