# development

Read the project's AGENTS.md, CONTROL.md, applicable governance, and canonical task first. Follow Owner authority and current gates. Use project-root-relative artifact paths; update the existing task rather than creating a parallel registry. Load only relevant context. This skill is portable Markdown and requires no BMAD runtime.

Use Executor responsibility. Confirm scope, dependencies, gates and revision; claim a role assignment before editing. Investigate relevant source, create a concise implementation plan in the task, and implement the smallest coherent change using project conventions. Add or update tests suited to the behavior. Record actual checks and results separately. Submit a review target with intent, changed files, and revision; independent reviewers form their own judgments. Triage and fix findings through CONTEXT_WORKFLOW. If a plan or requirement is wrong, return to that layer rather than hiding the issue in code. Checkpoint and return a bounded result; no implicit commit, push, deployment or next-task dispatch.
